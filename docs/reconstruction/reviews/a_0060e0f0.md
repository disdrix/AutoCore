## Seal: `+0x24` = **Laps** (not generic visit weight)

| Evidence | Location | Confidence |
|----------|----------|------------|
| GetFlags XML dumps `<Laps>%i</Laps>` with **`mov eax,[esi+0x24]; push eax`** | `0x0060e260` image: `…5d 8b 46 24 50 68 a4049e00…` | **High** |
| Loop count for `<GenericTargetCOID>` is `req+0xd0` | same GetFlags body | **High** |
| Server XML field `<Laps>` → `ObjectiveRequirementPatrol.Laps` | `ObjectiveRequirementPatrol.cs` | **High** (parity) |
| GetTarget uses product `+0x24 * +0xd0` for done; modulo **`+0xd0` only** for waypoint index | `0x0060e370` | **High** |

**Conclusion:** `req+0xd0` = listed waypoint/target count; `req+0x24` = **Laps** (how many full passes of the list). Threshold product = **needed pad count** = `targets * Laps`. Prior “visitWeight” plate name is a misnomer for Laps.

“Always 1?” — **No as field semantics.** Multi-lap is first-class (product, GetTarget modulo, server `NeededCount`). Sample mission XML often authors `<Laps>1</Laps>`; that is data, not a frozen constant in Eval.

## Seal: zero-product edge (Eval)

```
needed = (int)req[+0xd0] * (int)req[+0x24]   // imul
if ((float)needed <= slotFloat) return 1; else return 0;
```

| Case | Client Eval | Notes |
|------|-------------|--------|
| `targets*Laps == 0` | completes for any `slotFloat >= 0` | `(float)0 <= slot` |
| Action denom 0 | returns `1.0` | sibling contract |
| Server `Laps <= 0` with targets>0 | **normalizes Laps→1** in `NeededCount` | **diverges** from raw client product |
| Server targets==0 | `NeededCount` returns 1 | also diverges from client product 0 |

**Sealed for Eval:** zero product is immediately complete on non-negative progress. Server normalization is a **port caution**, not a client CF change.

## Surviving contract
