## Seal: C2S / S2C demux = **direction, not content**

| Evidence | Location | Confidence |
|----------|----------|------------|
| S2C dispatch only: `case 0x203e: Client_RecvInventoryUnequipNotify(); return 1` | `Client_PacketDispatch` `0x00815710` | **High** |
| C2S builder writes `auStack_30[0]=0x203e` then `Client_SendSectorPacket(..., 0x30, …)` | `Client_SendInventoryUnequip` `0x00862c00` | **High** |
| Sibling response opcode is **different**: `case 0x203f → Client_RecvInventoryUnequipResponse` | same dispatch | **High** |
| No content-bit or header field branches send vs receive | both bodies | **High** |

**Conclusion:** Same opcode number is **bidirectional**. Demux is **transport direction**:

- **S2C** → sector receive → `PacketDispatch` → `RecvInventoryUnequipNotify`
- **C2S** → UI/item path → `SendInventoryUnequip` → `SendSectorPacket`

There is **no** shared demuxer that inspects the 0x30 body to choose send vs receive.
