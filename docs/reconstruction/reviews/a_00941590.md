**Why skill id survives:** `Client_Skill_ResolveCastTarget` third formal is **`&tfid0`** (LEA after three success pushes → `ESP0+8` = arg1), **not** `&nSkillId`. Resolve **reads** seed TFID from arg1..4 and **writes** result into first-arg scratch (`auStack_114`); return EAX = out buffer. Arg0 skill id at `ESP0+4` is never written by resolve/equals.

**Cross-path:** QB activate (`0x00921b50`) stores `skill+0x5fc` at `+0x18` (same skill-id field). AutoCore `RequestCastSkillPacket` reads skill id at that slot.
