## Role

**Find a node by key in a custom hash map** and write an iterator (node pointer or end sentinel) through a stack out-parameter.

Primary observed consumer: `NDResourceCache_LookupOrCreate` (`0x0075dba0`) — map lookup before insert/factory path. Also used widely by resource/effect/name tables (20 xrefs).

---

## ABI (byte-sealed; decompiler hides register formals)

```c
// EDI = map*; EBX = key*; stack out_it*; ret 4; returns out_it* in EAX
void **HashMap_FindIterator_Inferred(void **out_it /* stack */);
// side formals (caller-set registers, not stack):
//   EDI = HashMap*
//   EBX = KeyObject*  (first dword compared; *key used as char* for hash)
```

| Slot | Role | Evidence |
|---|---|---|
| EDI | map / container | `mov esi,[edi+0x20]`, all field refs |
| EBX | key object* | `mov eax,ebx` before hash; `mov edx,[ebx]` in loop |
| `[esp+4]` / after frame → EBP | out iterator* | `mov ebp,[esp+0xc]`; `mov [ebp],…`; `ret 4` |
| EAX | returns `out_it*` | `mov eax,ebp` all epilogues |

MSVC often registers map+key across a call when the helper is `__fastcall`-like with extra EBX; treat as **custom register ABI** sealed by bytes + callers.

## Map layout (body-backed)

| Offset | Width | Role |
|---|---|---|
| `map+0x08` | ptr | **end sentinel** written on miss |
| `map+0x14` | ptr | **bucket table** base (`node*` slots) |
| `map+0x20` | u32 | **hash mask** (`hash & mask`) |
| `map+0x24` | u32 | **bucket count** (fold when index ≥ count) |

## Node layout (body-backed)

| Offset | Width | Role |
|---|---|---|
| `node+0x00` | ptr | **next** in bucket chain |
| `node+0x08` | u32 | **key dword** (compared to `*key`) |

Value payload (e.g. resource*) lives past the key for cache nodes (caller duals use `node+0x0C`) — **not read by this find body**.

## Algorithm

```
mask = map->mask (+0x20)
h = StringHashELF(key)          // FUN_0043b870: *key as char*
idx = h & mask
if (idx >= map->bucket_count (+0x24)):
  idx += -1 - (mask >> 1)

start = table[idx]
end   = table[idx + 1]          // adjacent slot
for node = start; node != end; node = node->next:
  if node->key (+8) < *key: continue
  if node->key > *key:  *out = map->end (+8); return out
  // equal:
  *out = node; return out
*out = map->end; return out
```

Bucket chains are **key-ordered** (early exit on greater key) — not a pure unordered list scan.

## Hash leaf (`FUN_0043b870`, context)

```c
// EAX = key object on entry
// str = *(char**)key
// h = 0; for each c in str: h = h*0x10 + c; if (h & 0xf0000000) h ^= (h & 0xf0000000) >> 24
```

Equality in find is **dword identity** of `*key` vs `node+8`, not `strcmp`. Content hash + pointer/id equality is consistent with interned string keys or opaque id keys whose low dword is the compare field.
