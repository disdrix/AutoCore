## Purpose

**UI message handler** for an inventory / item-use panel host. Dispatches on **`(msg, controlId)`**:

- Slot controls **`0x9c43..0x9c46`** (4 slots, index `controlId - 0x9c43`)
- Close/special **`40000` (`0x9c40`)** and **`0x9c41` / `0x9c42`**
- Unknown ids / msgs → **`UI_DefaultMessageHandler`** (`FUN_0087b500`)

On slot message **`0xe`**: try **`Client_UseInventoryItem_Inferred(1)`**; on failure fall back to **`Client_SendUseObject_IfInteractable`**.

Not a packet builder itself — may *trigger* sealed use/use-object paths via callees.

### Note on `controlId == 40000` arm

Decompiler shows **no `return 1`** after `FUN_007fca10` when `msg==8`, and **no action** for other msgs — execution continues into the `else if` chain only when `controlId != 40000`. For `controlId == 40000` and `msg != 8`, control falls through to **`FUN_0087b500`**. For `msg == 8`, after leave host, falls through to default as well (no early return in decomp). Treat as **High from decomp**; product may still intend swallow — residual if bytes differ.

Actually re-read:

```
if (param_3 == 40000) {
  if (param_2 == 8) {
    FUN_007fca10();
  }
}
else if (param_3 == 0x9c41) {
...
}
uVar6 = FUN_0087b500(param_2,param_3);
return uVar6;
```

So after 40000+msg8 leave, **still** falls into default handler. **Sealed as written.**
