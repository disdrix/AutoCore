## Machine-level notes

- **No SEH** (unlike twin `0x0040fb90` which wraps the same link logic in `LAB_009bc7d0`).
- Body hex (`read_memory`):
  - `push 0xC` / `call operator_new` / `add esp,4`
  - `test eax,eax` / `jz +2` / `mov [eax],eax`  → next = self
  - `lea ecx,[eax+4]` / `test ecx,ecx` / `jz +2` / `mov [ecx],eax` → prev = self
  - bare `ret` (`C3`); **EAX remains node\***
- Second `test ecx` is always true for valid heap (`node+4==0` only if `node==-4`).
- On null `operator_new`, second store would target `0x4` — relies on non-null new (MSVC throw/never-null path).
- Dword @ `+0x8` never written here (payload/pad; filled when nodes inserted).
- Callers always store return as list head and zero adjacent size dword (e.g. PalantirEnv `param_1[0x3a]=node; param_1[0x3b]=0`).

## Pseudocode (annotated)

```c
// EAX = node*; decompiler void is WRONG
void* StdList_AllocSentinel_0xC_Inferred(void)
{
  void *node = operator_new(0xC);
  if (node != NULL) {
    *(void**)node = node;            // next = self
  }
  if ((uint32_t*)((int)node + 4) != NULL) {
    *(uint32_t*)((int)node + 4) = (uint32_t)node; // prev = self
  }
  return node; // EAX
}
```
