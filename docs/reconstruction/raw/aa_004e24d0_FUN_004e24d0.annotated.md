## Machine-level notes

- **Role:** relocate dword POD half-open range `[srcBegin, srcEnd)` so that the range **ends at** exclusive end pointer `destEndExcl`.
- **Size math:** `count = (srcEnd - srcBegin) >> 2`; `size = count * 4` (via double `add eax,eax`, not `lea`).
- **Dest:** `destEndExcl - size` then `memmove(dest, srcBegin, size)`.
- **ABI:** three stack args; **bare `ret`** (cdecl). Distinct from sibling `Mem_MoveDwordRange_ReturnEnd` (`0x004e2e80`, stdcall `ret 0xC`, dest = param3, returns end).
- **Sole callee:** CRT `memmove` via IAT `@ 0x009c652c`.
- **Return:** void (EAX = memmove return but discarded by decompiler/callers as void).

## Pseudocode (annotated)

```c
// void Mem_MoveDwordRange_ToExclusiveEnd(void *srcBegin, int srcEnd, int destEndExcl)
// cdecl; bare ret
void FUN_004e24d0(void *param_1, int param_2, int param_3)
{
  int count = (param_2 - (int)param_1) >> 2;          // dword count
  memmove((void *)(param_3 + count * -4), param_1, count * 4);
  // dest = destEndExcl - size; size = count * 4
  return;
}
```

## Call-site pattern (vector insert in-place shift)

Callers pass:
1. `first` — start of tail range to shift
2. `last` — exclusive end of that range
3. `newEnd` — exclusive end after growth (`oldEnd + n * sizeof(dword)`)

Effect: `[first, last)` lands ending at `newEnd` (right-shift hole for insert fill).
