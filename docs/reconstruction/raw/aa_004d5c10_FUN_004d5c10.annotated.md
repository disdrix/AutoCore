## Machine-level notes

- **Role:** Client/sector **mission interact** processor: resolve interact TFID + character, clear mission staging, then either (A) **type-0x3a mission-giver path** — stage active turn-ins, build offerable mission vector, fill rolled rewards via `FUN_004d08c0` — or (B) **type-0 reward table path** via `FUN_004cf100` when a hash hit on `char[0x152]` supplies a def blob.
- **ABI:** Free function, **`ret 0xC`**, three stack formals. SEH frame (`LAB_009a2118`). Not thiscall entry (`mov ebx,[esp+…]` arg0).
- **param_1:** `TFID_16*` block — `Object_ResolveFromTFID(param_1)` = player/object; `param_1[1].dwCoidLo/Hi` fed to `CVOGReaction_ResolveObjectTarget` = interact target (NPC/object).
- **param_2:** `int*` out — written with resolved identity from `vtbl+0x1d8` on linked objects / interact target paths.
- **param_3:** opaque roll/context forwarded into `FUN_004d08c0(def, character, param_3)` on reward fill.
- **Gate type `0x3a`:** `*(int*)(*(int*)(target+0xa8)+0x38) == 0x3a` — product “mission interact object” class/type id (English open; numeric sealed).
- **Character pipeline:** after resolve, `character = vtbl+0x210(obj, 0)`; on null → early cleanup. Then `FUN_0052d8b0(char, 0, -1)` full staging clear.
- **Staging maps on character (index form `piVar8[N]` = dword index):**
  - `[0x14c]` — mission/active hash (chain walk by key)
  - `[0x14e]` — completed / journal hash
  - `[0x150]` — active mission hash (+ lock byte `+0x1d`)
  - `[0x152]` — alternate interact/def hash (type-0 path)
- **Type-0x3a major blocks:**
  1. Optional linked COID vector at `target+0x1d8/+0x1dc` (count `>> 3`); resolve first via `FUN_004e25d0`; if local list fills and nested type `== 0x12`, set `*param_2` from `vtbl+0x1d8`.
  2. If `*param_2 != 0`: walk hash cursor `FUN_00411900` / `FUN_00402c40`; match staging payload `+0x20/+0x24` to NPC CBID (`…+0xac→+0x34`) and continent (`…+0xa8→+0xfc`); on match `FUN_0052c700`, `FUN_0052b420` turn-in ready → invert to byte at staging payload `+0x2c` via `FUN_0052dac0`.
  3. Build offer vector locals (`pvStack_28` / `puStack_18`):
     - If `target+0x234` vector non-empty: scan region missions, match byte key in `[0x234,0x238)`, check requirements / completed; push via `FUN_004e54a0`. Cap path: if >7 short-`+0xac` entries → toast `FUN_00691630`×2 and abort.
     - Else if `target+0x244` vector: iterate mission ids, skip if active in `[0x150]`; completed branch may re-offer if short@pad == -1 and requirements ok; else global table via `FUN_0053fff0`.
  4. Fallback continent scan via `FUN_004e26d0` / `FUN_004e1830` when no vector pick.
  5. Merge temp vectors (`FUN_004e39d0`), `FUN_004e4b10`, then for each selected mission id: skip if already active in `[0x150]`; else stamp payload CBID/continent/`+0x28` and **`FUN_004d08c0(missionDef, character, param_3)`** rolled rewards.
- **Non-0x3a path:** `CNDHash_LookupByKey(char[0x152], field from param_1[1])`; on hit take `+0x14c` def ptr, `FUN_004cf100` type-0 fill, re-resolve `param_1+2` TFID, set `*param_2`, patch turn-in ready byte `+0x2c`.
