## Machine-level notes

1. **Entry gate `+0x6B4`:** same numeric gate shape as convoy pack. Continue if `target+0x6B4 < 1` **or** `local+0x6B4 >= 1`; else early out. English of field open (level/rank-like).
2. **`DAT_00d1da30`:** non-null clan **table host**. Also **ECX this** for both `FUN_004c22a0` lookups.
3. **Key pair:** from object via `*(obj+4)` → secondary `+4` base, then `base + obj + 0x164` / `+0x168` (two dwords). Membership/clan identity keys.
4. **`FUN_004c22a0`:** linear scan of `this+0x1E4..+0x1E8` pointer vector for entry with `(*e==key_lo && e[1]==key_hi)`; returns entry* or 0.
5. **Invite** when local has clan entry, target has **none**, and `*(localClan+0x24) >= 2` (rank/authority threshold).
6. **Kick** when both have entries and `*(targetClan+0x24) < *(localClan+0x24)` (strict lower rank field). No explicit same-clan compare in this unit.
7. **Button helper `FUN_0082f7d0`:** `ECX=host`, `EDX=0xFFFFFFFF`, stack label/xml/0/id → host `vtbl+0x444` create + btn `vtbl+0x1D8` set text.
8. **Slots:** Invite → `host+0x548`; Kick → `host+0x54C` (convoy peer uses `+0x540`/`+0x544`).
9. **Ids:** Invite `0x11173`, Kick `0x11174` (convoy `0x11171`/`0x11172`).
