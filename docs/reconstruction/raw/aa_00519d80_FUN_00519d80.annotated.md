## Machine-level notes

- **ABI:** `__thiscall` — ECX=`this` object (`8B F1`); **one stack formal** (death context / reason); final **`C2 04 00`** (`ret 4`).
- **SEH:** frame `LAB_009a36ba`; scope around HB `operator_new(0x24)` + ctor `FUN_005dabc0`.
- **Product string:** `"##$$…ONDeath Object CBID:%i, Geo:%s, COID:%I64d, Global?:%i, Position: … being added to delete cue, but still in InactiveObjectsHas.\n"` — seals **OnDeath** + delete-queue / InactiveObjects hash warning (same family as `Object_QueueDelete` `0x004d4790`).
- **Multi-vtbl:** DATA xrefs at `0x009ce29c`, `0x009d3414`, `0x009d419c`, `0x009dbc4c`.
- **Stack formal gate:** decompiler `unaff_retaddr` is the stack formal; used with `(this+0x28/0x2C mask) != -1` before `FUN_004d2700`.
- **Float:** `_DAT_009cec58` = `F0 00 F0 3A` ≈ **0.001831f** — scales random ushort before ROUND for HB delay/id path.
- **Flag seal:** `*(byte*)(this+0x17d) |= 1` on both death paths (bit 0 at flags region; peer `Object_QueueDelete` uses bit 1 via `this[0x5f] |= 2` at `+0x17c`).
- **Decompiler gaps:** late return `unaff_ESI >> 0x18` is artifact; epilogue loads AL from stack temp. `CNDDoubleList` path shows `_DAT_00000000` after remove (list head recovered at runtime). Prefer CF order over register names.
